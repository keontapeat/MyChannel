## Key Design Patterns for MyChannel iOS
- Use **async/await** for all network calls and async operations (Swift 5.5+)
- Use **@MainActor** for UI updates
- Prefer **Actors** for thread-safe shared state
- Use **Combine** or **AsyncSequence** for reactive streams
- Follow **MVVM** pattern: Views → ViewModels → Services
- Use **dependency injection** for testability
- Implement **proper error handling** with Result types
- Use **Codable** for JSON serialization
- Implement **offline-first** where possible with local caching
- Use **LazyVStack/LazyHStack** for performance in long lists
- Implement **proper memory management** (weak/unowned references in closures)

## Common Pitfalls to Avoid
- Don't use `@ObservedObject` when you mean `@StateObject` (causes re-initialization)
- Don't perform heavy work on the main thread
- Don't create retain cycles in closures (use `[weak self]`)
- Don't ignore memory warnings
- Don't block the UI thread with synchronous network calls
- Don't use force unwrapping (`!`) without proper justification
- Don't ignore accessibility
- Don't hardcode strings (use localization)
- Don't skip error handling
- Don't use deprecated APIs

## MyChannel-Specific Conventions
- Deployment target: **iOS 15+**
- Swift version: **5.9+**
- Xcode: **15+**
- Use `AppConfig` for configuration
- Use `AppSecrets` for sensitive data (never hardcode)
- Use `AppTheme` for consistent styling
- Follow `.swiftlint.yml` rules
- Namespace features under `MyChannel/Features/`
- Core utilities under `MyChannel/Core/`
