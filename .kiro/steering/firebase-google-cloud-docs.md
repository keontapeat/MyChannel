## MyChannel Firebase Architecture

### Collections Structure
```
users/{userId}
  - profile data, settings, KYC status
  
channels/{channelId}
  - channel metadata, stats, monetization
  
videos/{videoId}
  - video metadata, URLs, stats
  
vsMatches/{matchId}
  - wager details, participants, status
  
escrow/{escrowId}
  - money held in escrow for matches
  
transactions/{txId}
  - financial transaction log
  
notifications/{notificationId}
  - user notifications
  
chats/{chatId}/messages/{messageId}
  - live chat messages
```

### Security Rules Principles
- **Authenticate everything**: No unauthenticated writes
- **Validate data**: Check types, ranges, required fields
- **Authorize carefully**: Users can only modify their own data
- **Money is read-only**: Only Cloud Functions can write to escrow/transactions
- **Rate limit**: Prevent spam and abuse
- **Audit log**: Track all money-related operations

### Cloud Functions Organization
```
functions/
  auth/          - User auth triggers
  video/         - Video processing
  match/         - VS Match logic
  payment/       - Payment processing
  notification/  - Push notifications
  moderation/    - Content moderation
  analytics/     - Data aggregation
```

### Performance Best Practices
- **Batch writes**: Use batched writes for multiple operations
- **Transactions**: Use for money operations (atomic)
- **Indexes**: Create composite indexes for complex queries
- **Pagination**: Use cursor-based pagination for large lists
- **Caching**: Cache frequently accessed data (Redis/Memorystore)
- **Denormalization**: Duplicate data to avoid joins
- **Aggregation**: Pre-compute stats in Cloud Functions
- **Offline support**: Enable offline persistence on mobile

### Cost Optimization
- **Firestore**: Minimize reads with caching and pagination
- **Storage**: Use CDN for frequently accessed files
- **Functions**: Use 2nd gen for better performance/cost
- **Bandwidth**: Compress data, use CDN
- **Logging**: Set appropriate log retention periods

### Monitoring & Alerts
- **Error rate**: Alert on function error spikes
- **Latency**: Monitor p95/p99 response times
- **Quota**: Track Firestore read/write quotas
- **Cost**: Set budget alerts
- **Security**: Monitor auth failures and suspicious activity

## Common Patterns for MyChannel

### Atomic Money Operations
```javascript
const db = admin.firestore();
await db.runTransaction(async (transaction) => {
  // Read current balances
  // Validate sufficient funds
  // Update escrow
  // Update user balances
  // Log transaction
});
```

### Real-time Chat
```javascript
// Use Realtime Database for chat (better for real-time)
const chatRef = admin.database().ref(`chats/${matchId}/messages`);
await chatRef.push({
  userId,
  message,
  timestamp: admin.database.ServerValue.TIMESTAMP
});
```

### Video Processing Trigger
```javascript
exports.processVideo = functions.storage.object().onFinalize(async (object) => {
  // Transcode video
  // Generate thumbnails
  // Extract metadata
  // Update Firestore
  // Notify user
});
```

### Scheduled Cleanup
```javascript
exports.cleanupExpiredMatches = functions.pubsub
  .schedule('every 1 hours')
  .onRun(async (context) => {
    // Find expired matches
    // Refund escrow
    // Update status
  });
```

### Callable Function (Client → Server)
```javascript
exports.createVSMatch = functions.https.onCall(async (data, context) => {
  // Verify auth
  // Validate input
  // Check compliance (age, KYC, limits)
  // Create match
  // Lock escrow
  // Return match ID
});
```

## Security Checklist
- ✅ All functions verify `context.auth` (authenticated)
- ✅ Input validation on all user data
- ✅ Rate limiting on expensive operations
- ✅ Secrets in Secret Manager (never in code)
- ✅ HTTPS only (no HTTP)
- ✅ CORS configured properly
- ✅ Security Rules tested and deployed
- ✅ Audit logging for money operations
- ✅ Error messages don't leak sensitive data
- ✅ Dependencies regularly updated
